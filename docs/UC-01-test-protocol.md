# Протокол тестування UC-01 — Бронювання квитка

## Мета тестування

Перевірити коректність роботи функції бронювання автобусного квитка, обробку некоректних запитів та запобігання повторному бронюванню одного місця на одному рейсі.

## Тест 1 — Успішне бронювання вільного місця

**Вхідні дані:**
- TripId: 1
- SeatId: 12

**Дія:** Надіслати запит на бронювання вільного місця.

**Очікуваний результат:**
- HTTP 201 Created.
- Бронювання створено.
- Повертається ID бронювання.
- Дані рейсу та місця відповідають запиту.

## Тест 2 — Повторне бронювання того самого місця

**Вхідні дані:**
- TripId: 1
- SeatId: 12

**Дія:** Повторно надіслати запит на бронювання вже зайнятого місця.

**Очікуваний результат:**
- HTTP 409 Conflict.
- Відображається повідомлення про зайняте місце.
- Нове бронювання не створюється.
- Колекція бронювань не змінюється.

## Тест 3 — Бронювання того самого місця на іншому рейсі

**Вхідні дані:**
- TripId: 2
- SeatId: 12

**Дія:** Забронювати місце 12 на іншому рейсі.

**Очікуваний результат:**
- Бронювання дозволяється, якщо на рейсі 2 місце 12 ще вільне.
- HTTP 201 Created.

## Тест 4 — Некоректний номер рейсу

**Вхідні дані:**
- TripId: 0
- SeatId: 12

**Очікуваний результат:**
- HTTP 400 Bad Request.
- Бронювання не створюється.

## Тест 5 — Відсутній номер місця

**Вхідні дані:**
- TripId: 1
- SeatId: порожній рядок.

**Очікуваний результат:**
- HTTP 400 Bad Request.
- Бронювання не створюється.

## Результати тестування UC-01

| № | Тестовий сценарій | Очікуваний результат | Фактичний результат | Статус |
|---|---|---|---|---|
| 1 | Бронювання вільного місця (TripId = 1, SeatId = 12) | HTTP 201 Created, бронювання створено | Бронювання успішно створено. Повернуто HTTP 201 Created, дані бронювання та унікальний ID | Пройдено |
| 2 | Повторне бронювання того самого місця на тому самому рейсі | HTTP 409 Conflict, дані не змінюються | Система відхилила повторне бронювання, повернула HTTP 409 Conflict. Нове бронювання не створено | Пройдено |
| 3 | Бронювання того самого місця на іншому рейсі (TripId = 2) | HTTP 201 Created | Бронювання успішно створено. Система дозволяє бронювати однаковий номер місця на різних рейсах | Пройдено |
| 4 | Некоректний ID рейсу (TripId = 0) | HTTP 400 Bad Request | Система відхилила запит із некоректним ID рейсу та повернула HTTP 400 Bad Request | Пройдено |
| 5 | Порожній номер місця (SeatId = "") | HTTP 400 Bad Request | Система відхилила запит із порожнім номером місця та повернула HTTP 400 Bad Request | Пройдено |

### Підсумок тестування

За результатами тестування всі 5 тестових сценаріїв виконано успішно. Функціональність UC-01 «Бронювання автобусного квитка» відповідає визначеним вимогам. Усі перевірки пройшли без помилок.

**Загальний результат: 5 із 5 тестів пройдено (100%).**
